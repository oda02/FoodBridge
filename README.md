# FoodBridge

Android-приложение для добавления, исправления и удаления питания в Health Connect по ссылке. В одной ссылке передаётся от 1 до 20 операций; сайт показывает их предпросмотр и предлагает установить APK.

- Репозиторий: [github.com/oda02/FoodBridge](https://github.com/oda02/FoodBridge)
- Сайт: [food.kukakur.ru](https://food.kukakur.ru/)
- APK: [FoodBridge.apk](https://food.kukakur.ru/downloads/FoodBridge.apk)
- Конфиденциальность: [food.kukakur.ru/privacy/](https://food.kukakur.ru/privacy/)

Текущая конфигурация приложения: **1.2.0, versionCode 3**, Android **14+**. Результаты сборки, публикации и проверки на телефоне фиксируются отдельно; наличие инструкции не означает, что конкретный выпуск уже проверен на устройстве.

## Инструкция для ChatGPT

[Готовый гайд FoodBridge-ChatGPT.md](docs/FoodBridge-ChatGPT.md): подключение к чату/проекту, формирование ссылок, журнал ID, исправления, удаление и пакеты.

## Как пользоваться

1. Установите подписанный APK на Android 14 или новее. При установке из браузера Android может попросить разрешить установку приложений для этого браузера.
2. Разрешите FoodBridge **запись питания** в Health Connect. Дополнительное разрешение на чтение питания других приложений не запрашивается.
3. Откройте ссылку, проверьте перечисленные операции и подтвердите выполнение. Для исправления передаются тот же ID и большая ревизия; для другого съеденного блюда нужен новый ID.
4. Проверьте результат в Health Connect. При частичном сбое смотрите результаты отдельных операций; повторная ссылка пропустит уже завершённые ревизии.

В настройках можно включить автодобавление. Оно распространяется на пакеты `upsert` с допустимыми временем и значениями. **Наличие хотя бы одного удаления требует ручного подтверждения всего пакета**, даже при включённой автоматике. Необычно большие нутриенты также требуют подтверждения. Время будущего блюда не допускает сохранение.

Health Connect встроен в Android 14+. Его доступность зависит от устройства и профиля; рабочие профили не поддерживаются. Разрешение можно отозвать в настройках Health Connect. [Доступность платформы](https://developer.android.com/health-and-fitness/health-connect/availability).

Если открывается сайт, включите Android → Приложения → FoodBridge → Открывать по умолчанию → Открывать поддерживаемые ссылки. Затем снова нажмите исходную ссылку. Встроенный браузер мессенджера может удерживать переход внутри себя; попробуйте системный браузер. Сайт не выполняет операции в Health Connect.

## Архитектура и данные

```text
ChatGPT / другое приложение
  → HTTPS-ссылка с JSON во фрагменте #
    → Android App Link → список операций → Health Connect
    → браузер → локальный предпросмотр и установка APK
```

| Часть | Ответственность |
| --- | --- |
| `app/` | Kotlin/Compose, входящие ссылки, список операций и подтверждение |
| `RequestParser` | Единственный конверт `items`, 1–20 операций, уникальные ID, строгая структура |
| `DeepLinkParser` | UTF-8/Base64URL, поля блюда, ревизии и ограничения значений |
| `FoodViewModel` | Разрешения, автоматический/ручной запуск, результаты и новые интенты |
| `HealthConnectRepository` | Запись/удаление NutritionRecord и точечное чтение собственных записей |
| Координатор операций | Общая блокировка, сравнение ревизий, последовательный запуск и повторы |
| `Settings` | DataStore: настройка и до 1000 хешей ID с максимальной известной ревизией |
| `site/dist/` | Готовые HTML/CSS/JS, обработка фрагмента локально в браузере |
| `deploy/food.kukakur.ru.caddy` | Отдельный виртуальный хост существующего Caddy |
| `docs/` | Обзоры Android/безопасности и публичный отпечаток сертификата |

Аккаунтов, серверной базы блюд и аналитики нет. Перед операцией приложение точечно читает **собственную** запись по client ID: проверяет ревизию и может показать название удаляемого блюда. Android позволяет читать собственные записи с правом записи; `READ_NUTRITION` для этого не требуется. Содержимое других приложений не запрашивается. Названия и нутриенты не сохраняются в локальной истории и не отправляются разработчику. [Правила HealthConnectManager.readRecords](https://developer.android.com/reference/android/health/connect/HealthConnectManager).

Фрагмент URL после `#` не входит в HTTP-запрос к сайту. Base64URL — кодирование, а не шифрование: ссылку видят участники переписки, а браузер или мессенджер может сохранить её в истории. Не публикуйте личные ссылки, если не хотите раскрыть их содержимое.

## Единственный формат запроса

```text
https://food.kukakur.ru/#BASE64URL_UTF8_JSON_WITHOUT_PADDING
```

Используйте HTTPS, точный домен и корневой путь `/`, без query, порта и userinfo. JSON кодируется в UTF-8, затем в Base64URL без завершающих `=`. Полная ссылка ограничена 12 000 символами; весь JSON — 8192 байтами. Лимит размера действует и для пакета из 20 операций.

Корневой объект содержит только `items`. Даже одна операция передаётся в массиве. Внутри одного запроса каждый `id` встречается один раз: исправление и удаление того же блюда нельзя включить одновременно.

```json
{
  "items": [
    {
      "op": "upsert",
      "id": "example-oatmeal-2026-09-10",
      "rev": 1,
      "name": "Овсянка с бананом",
      "kcal": 420,
      "time": "2026-09-10T09:00:00+03:00",
      "p": 16,
      "f": 12,
      "c": 62,
      "fiber": 8,
      "meal": "breakfast"
    }
  ]
}
```

| Поле операции | Обязательно | Значение |
| --- | --- | --- |
| `op` | Да | `upsert` либо `delete` |
| `id` | Да | Непустой стабильный ID конкретного блюда до 200 символов; рекомендуется UUID |
| `rev` | Для delete; для upsert по умолчанию 1 | Положительное JSON-целое 1–1 000 000; для delete минимум 2 |
| `name` | Для upsert | Непустое название до 200 символов |
| `kcal` | Для upsert | Число, килокалории, 0–20 000 |
| `time` | Для upsert | ISO 8601 с секундами и явным смещением либо `Z` |
| `p`, `f`, `c` | Нет, только upsert | Белки, жиры, углеводы в граммах, каждое 0–5000 |
| `fiber`, `sugar`, `saturatedFat` | Нет, только upsert | Клетчатка, сахар, насыщенные жиры в граммах, каждое 0–5000 |
| `sodiumMg` | Нет, только upsert | Натрий в миллиграммах, 0–100 000 |
| `meal` | Нет, только upsert | `breakfast`, `lunch`, `dinner`, `snack`, `other`; по умолчанию `other` |

`rev` пишется как `2`, а не `2.0`, `2e0` или `"2"`. Числовые нутриенты передаются числами, не строками. Время допускает 1–9 знаков дробной секунды, годы 1970–2100 и явное смещение. Управляющие символы в строках, повторяющиеся/неизвестные ключи, недопустимые вложенные структуры и `null` вместо необязательного значения отклоняются. Отсутствующий нутриент остаётся неизвестным; явный ноль записывается как ноль.

Для upsert клетчатка `fiber` отображается на `NutritionRecord.dietaryFiber`, натрий — через `Mass.milligrams`. Интервал записи: указанное время плюс 60 секунд; смещение сохраняется. Используется `Metadata.manualEntry`.

Необычными для автоматического режима считаются `kcal > 4000`, любой нутриент в граммах `> 500` или `sodiumMg > 10000`. Это пороги подтверждения, не медицинская оценка.

### Добавить или исправить

`upsert` создаёт запись, если её нет, либо заменяет существующую при большей ревизии. Для исправления сохраните ID и увеличьте `rev`; повторите **полное новое состояние** блюда. Это не частичный patch: непереданный необязательный нутриент не наследуется, а становится неизвестным. Время оставляйте прежним, если исправляете только состав.

### Удалить

Удаление содержит ровно три поля:

```json
{
  "items": [
    {"op": "delete", "id": "example-oatmeal-2026-09-10", "rev": 2}
  ]
}
```

Нужна ревизия больше уже применённой. Операция удаляет только собственную запись FoodBridge с этим ID. Отсутствующий объект даёт результат «уже отсутствует», а не сообщение о новом удалении. Удаление всегда подтверждается вручную. Для восстановления передайте полный `upsert` с тем же ID и ревизией больше удаления.

### Несколько операций

```json
{
  "items": [
    {
      "op": "upsert",
      "id": "example-lunch-2026-09-10",
      "rev": 1,
      "name": "Обед",
      "kcal": 650,
      "time": "2026-09-10T13:00:00+03:00",
      "p": 35,
      "f": 22,
      "c": 78,
      "meal": "lunch"
    },
    {"op": "delete", "id": "example-oatmeal-2026-09-10", "rev": 2}
  ]
}
```

Пакет выполняется последовательно, а не одной общей транзакцией: часть операций может завершиться до ошибки другой. Приложение показывает результаты; уже выполненное не откатывается. При повторе той же ссылки завершённые ревизии пропускаются. Не создавайте новые ID или ревизии только ради повтора после сбоя.

## Генератор Markdown-ссылки в PowerShell

Пример создаёт новое блюдо с текущим временем и выводит готовую ссылку:

```powershell
$food = [ordered]@{
    op = 'upsert'
    id = [guid]::NewGuid().ToString()
    rev = 1
    name = 'Овсянка с бананом'
    kcal = 420
    time = [DateTimeOffset]::Now.ToString("yyyy-MM-dd'T'HH:mm:sszzz")
    p = 16
    f = 12
    c = 62
    fiber = 8
    meal = 'breakfast'
}
$foodRequest = @{ items = @($food) }
$foodJson = $foodRequest | ConvertTo-Json -Depth 5 -Compress
$foodBytes = [Text.Encoding]::UTF8.GetBytes($foodJson)
$foodToken = [Convert]::ToBase64String($foodBytes).TrimEnd('=').Replace('+','-').Replace('/','_')
$foodUrl = 'https://food.kukakur.ru/#' + $foodToken
"[Добавить овсянку в Health Connect]($foodUrl)"
```

Сохраните `$food`, ID и максимальную отправленную ревизию. Для исправления измените `$food['kcal']`, другие нужные значения и задайте `$food['rev'] = 2`, затем повторите кодирование конверта. Для пакета передайте несколько объектов в `items`. Первый генератор при повторном запуске создаёт новый ID — это другая запись, а не исправление.

Готовый пример Markdown для демонстрационного блюда:

```markdown
[Добавить овсянку в Health Connect](https://food.kukakur.ru/#eyJpdGVtcyI6W3sib3AiOiJ1cHNlcnQiLCJpZCI6ImV4YW1wbGUtb2F0bWVhbC0yMDI2LTA5LTEwIiwicmV2IjoxLCJuYW1lIjoi0J7QstGB0Y_QvdC60LAg0YEg0LHQsNC90LDQvdC-0LwiLCJrY2FsIjo0MjAsInRpbWUiOiIyMDI2LTA5LTEwVDA5OjAwOjAwKzAzOjAwIiwicCI6MTYsImYiOjEyLCJjIjo2MiwiZmliZXIiOjgsIm1lYWwiOiJicmVha2Zhc3QifV19)
```

Пример — демонстрационные значения, не расчёт фактически съеденного блюда. Генератору или ChatGPT нужно передать реальные нутриенты, дату и часовой пояс.

## Ревизии, повторы и ограничения

В Health Connect используется `clientRecordId = "foodbridge:" + SHA256(id)` и `clientRecordVersion = rev`. Перед изменением приложение сверяет текущую собственную запись с локальной максимальной ревизией. Равная или меньшая ревизия считается повтором/устаревшей операцией и не изменяет данные. Большая ревизия upsert обновляет найденную запись или создаёт отсутствующую. [Правила upsert](https://developer.android.com/health-and-fitness/health-connect/write-data).

Удаление не имеет встроенной проверки ревизии в API Health Connect, поэтому её выполняет приложение перед удалением. После успеха или подтверждённого отсутствия объекта сохраняется локальная ревизия удаления — отметка, которая блокирует старые ссылки. Если удаление вернуло ошибку, приложение повторно проверяет наличие собственной записи: подтверждённое отсутствие позволяет завершить повтор; ошибка чтения не считается отсутствием. [Удаление по client ID](https://developer.android.com/health-and-fitness/health-connect/delete-data).

История ограничена 1000 ID и не содержит нутриентов. Если запись существует в Health Connect, её ревизия позволяет восстановить проверку после потери локальной истории. Если она удалена и локальная отметка тоже потеряна после очистки, переустановки или вытеснения, восстановить максимальную ревизию удаления уже неоткуда: старая upsert-ссылка может создать блюдо заново. Сохраняйте ID/ревизии в источнике ссылок и проверяйте результат в Health Connect.

Общая блокировка упорядочивает операции этого приложения. Она не превращает несколько API-вызовов в транзакцию Health Connect и не блокирует действия пользователя внутри системного приложения. Автоматическое выполнение подходит только для ссылок из доверенного источника; совпадение домена и корректный формат не удостоверяют отправителя.

### Подпись: использовать существующий ключ

Для этого приложения уже создан постоянный ключ:

```text
E:/Projects/FoodBridge/private/foodbridge-release.p12
```

Его alias — `foodbridge`. Настройка находится в `E:/Projects/FoodBridge/signing.properties`; шаблон её структуры:

```properties
storeFile=E:/Projects/FoodBridge/private/foodbridge-release.p12
storePassword=EXISTING_STORE_PASSWORD
keyAlias=foodbridge
keyPassword=EXISTING_KEY_PASSWORD
```

Это только схема, не файл для замены существующих настроек. **Не генерируйте новый ключ для обновления FoodBridge.** Сохраните защищённую резервную копию одновременно `.p12` и `signing.properties` вне рабочей копии; при переносе восстановите их и при необходимости исправьте только путь. Потеря ключа нарушит обновление установленного приложения и его связь с доменом. Оба файла и каталог `private/` исключены из Git. Пароли нельзя включать в публичные команды, логи, issue или README.

Публичный SHA-256 сертификата записан в `docs/release-certificate.txt`:


Проверяйте уже собранный APK через `apksigner verify --verbose --print-certs <APK>` из Android SDK Build Tools. Его SHA-256 должен совпадать с опубликованным `assetlinks.json`. Debug-подпись отличается; debug APK не проверяет связь production-домена с release-сертификатом. При будущем использовании Play App Signing потребуется отпечаток фактической подписи распространяемого Google Play APK. ## Публикация рядом с существующими сайтами Caddy

Целевой сервер: `158.160.139.53`, SSH-пользователь `aviloffo`. DNS A-запись `food.kukakur.ru` направлена на этот адрес. На сервере используется системный сервис `caddy`: `/etc/caddy/Caddyfile` импортирует `/etc/caddy/sites-enabled/*.caddy`. FoodBridge добавляет отдельный `/etc/caddy/sites-enabled/food.kukakur.ru.caddy` с корнем `/opt/foodbridge/site`.

1. Перед изменением изучите `systemctl cat caddy`, активный Caddyfile и существующие импорты. Сохраните резервные копии полного конфига, старого блока FoodBridge при его наличии и предыдущего каталога сайта. Не заменяйте общий Caddyfile содержимым одного блока.
2. Подготовьте отдельный staging-каталог из **всего** `site/dist/`, включая скрытый `.well-known`. Добавьте проверенный подписанный APK как `downloads/FoodBridge.apk` и корректный файл ассоциации. Не переносите на сервер ключ подписи, `signing.properties`, исходные данные блюд или весь проект.
3. Передайте staging через SSH/SCP и установите статические файлы в `/opt/foodbridge/site` с правом чтения для пользователя Caddy. При повторном релизе используйте отдельный каталог выпуска и атомарное переключение либо сохраняйте предыдущий каталог для отката.
4. Установите только блок из `deploy/food.kukakur.ru.caddy` в `/etc/caddy/sites-enabled/food.kukakur.ru.caddy`. Проверьте **полную конфигурацию**, затем выполните плавную перезагрузку:

```bash
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
sudo systemctl is-active caddy
```

Перезагрузку выполняйте только после успешной валидации. Нельзя передавать `caddy reload` конфигурацию лишь одного сайта: это заменит работающий набор маршрутов. При откате восстановите предыдущий блок/каталог, снова проверьте полный Caddyfile и перезагрузите сервис. [Команды Caddy](https://caddyserver.com/docs/command-line).

Caddy получает и продлевает сертификат автоматически при доступности домена и стандартных портов проверки. Если используется Cloudflare Proxy, настройка должна обеспечивать корректную проверку домена и безопасное соединение с origin; для прямой A-записи DNS API-токен не требуется. Файл ассоциации должен отвечать по HTTPS без редиректа. [Автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https).

Проверьте после публикации домашнюю страницу, `/privacy/`, APK и файл ассоциации, а также существующие соседние домены. Для shell-проверки используйте `curl.exe` в Windows или `curl` в Linux:

```bash
curl -I https://food.kukakur.ru/
curl -I https://food.kukakur.ru/privacy/
curl -I https://food.kukakur.ru/downloads/FoodBridge.apk
curl -i https://food.kukakur.ru/.well-known/assetlinks.json
```

У блока FoodBridge нет директивы access log; JSON блюда не передаётся в запросе. При изменениях общего логирования Caddy проверяйте также глобальные настройки: отсутствие локальной директивы само по себе не отменяет унаследованную конфигурацию.

## App Links

Статический файл `site/dist/.well-known/assetlinks.json` должен содержать ассоциацию с точным package name и сертификатом:

```json
[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": {
    "namespace": "android_app",
    "package_name": "ru.kukakur.foodbridge",
    "sha256_cert_fingerprints": [
      "D1:F8:D3:D2:ED:BB:C4:99:00:0F:8A:8F:B9:D2:47:83:C1:0B:1E:67:17:FA:4C:0F:C9:A4:36:92:79:9E:97:0F"
    ]
  }
}]
```

Файл общедоступен, не содержит секретов и обслуживается как `application/json`. Manifest использует `autoVerify=true`, HTTPS, `food.kukakur.ru` и корневой путь `/`; страницы установки/конфиденциальности остаются web-маршрутами. [Ассоциации сайта и приложения](https://developer.android.com/training/app-links/configure-assetlinks).

Установите именно release APK, подключите телефон к интернету и выполните:

```bash
adb shell pm verify-app-links --re-verify ru.kukakur.foodbridge
adb shell pm get-app-links ru.kukakur.foodbridge
```

Проверка асинхронна; подождите её завершения и повторите чтение статуса. Ожидается `food.kukakur.ru: verified`. Для независимого теста маршрутизации запустите ссылку без принудительного package/component:

```bash
adb shell am start -a android.intent.action.VIEW -c android.intent.category.BROWSABLE -d 'https://food.kukakur.ru/#PASTE_GENERATED_TOKEN'
```

Замените `PASTE_GENERATED_TOKEN` действительным токеном. Команда, которая явно указывает Activity или принудительно одобряет домен, проверяет только запуск и не доказывает верификацию. Для диагностики с чистым состоянием на тестовом устройстве можно сбросить состояние через `adb shell pm set-app-links --package ru.kukakur.foodbridge 0 all`, затем повторить верификацию. [Процедура Android](https://developer.android.com/training/app-links/verify-applinks).

## Телефон и ADB по Wi-Fi

На Android 14+ включите «Для разработчиков → Беспроводная отладка», подключите компьютер и телефон к одной сети, выберите сопряжение кодом. Само включение отладки не даёт компьютеру доступ: сначала нужно подтверждённое сопряжение.

```bash
adb pair PHONE_IP:PAIRING_PORT
adb connect PHONE_IP:DEBUG_PORT
adb devices -l
adb install -r app/build/outputs/apk/release/app-release.apk
```

Введите код в интерактивном запросе `adb pair`; pairing port и debugging port могут различаться. Используйте IP и порты с экрана телефона, а не адрес сервера сайта. При нескольких устройствах добавьте `-s DEVICE_SERIAL` после `adb`. Отладка продолжает работать, пока телефон и компьютер доступны друг другу и авторизация не отозвана; IP/порт могут измениться. Если mDNS не подключил ранее сопряжённый телефон автоматически, повторите `adb connect` с текущими данными. [Официальная инструкция](https://developer.android.com/studio/run/device).

Не удаляйте установленную release-версию ради переключения на debug без необходимости: сертификаты отличаются, а удаление приложения сбрасывает его настройки и локальную историю. Для проверки production App Links используйте подписанный release APK.

## Проверки и ограничения

Автоматические проверки запускаются Gradle-командой из раздела сборки. Тесты охватывают строгий разбор пакетов/некорректных входных данных, отображение нутриентов и координатор операций. Unit-тесты не заменяют реальную запись через платформенный Health Connect.

На физическом Android 16 проверьте: холодный/повторный запуск ссылки; поворот экрана и восстановление процесса; отказ и отзыв разрешения; возврат из Health Connect; две ссылки подряд и новую ссылку во время сохранения; ссылку из открытых настроек; повтор ID/ревизии и отклонение устаревшей версии; обновление и удаление с увеличением rev; отсутствующую запись; восстановление большей ревизией после удаления; смешанный пакет и частичный сбой; отсутствующие и нулевые нутриенты; будущее время; необычные значения и ручное подтверждение. Проверьте реальные значения созданной записи в Health Connect. Отдельно проверьте fallback в браузере без установленного приложения.

Приложение не проверяет достоверность нутриентов и не является средством медицинской оценки. Автодобавление следует включать только при доверии к источнику ссылок: другое приложение также может открыть экспортированную Activity. Ограничение домена и формат данных не аутентифицируют отправителя. По умолчанию запись требует подтверждения.

Технические обзоры находятся в `docs/android-review.md` и `docs/security-review.md`. Официальные материалы: [настройка Health Connect](https://developer.android.com/health-and-fitness/health-connect/get-started), [NutritionRecord](https://developer.android.com/reference/androidx/health/connect/client/records/NutritionRecord), [стабильные релизы SDK](https://developer.android.com/jetpack/androidx/releases/health-connect).
