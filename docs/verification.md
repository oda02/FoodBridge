## Проверка настоящего Health Connect

На отдельном эмуляторе установлен подписанный release APK. Это реальные операции провайдера, а не подмена API:

- одиночное добавление, исправление и повтор ссылки;
- окончательный подписанный APK: текущее время, ранее сегодня, вчера и другой timezone offset — реальные вставки успешны;
- отклонение старой ревизии после исправления;
- пакет добавление + исправление;
- получение названия собственной записи перед удалением с одним WRITE_NUTRITION;
- удаление, его повтор и защита от восстановления старой ссылкой;
- смешанный пакет восстановления новой ревизией и удаления другого блюда;
- автоматические пакетные добавления/исправления и возврат к предыдущему экрану;
- удаление при включённой автоматике остаётся на экране подтверждения;
- необычные значения и отсутствие разрешения блокируют автоматическую запись.

Частичные отказы, потеря ответа удаления, ошибка записи истории, параллельные вызовы и отмена coroutine проверены детерминированными тестами координатора. Ошибка в середине пакета не отменяет уже выполненное; повтор выполняет незавершённые операции.

На физическом телефоне ранее успешно добавлена тестовая запись «Творог + банан», 430 kcal; пользователь подтвердил её появление скриншотом приложения здоровья. Новые сценарии удаления и пакетов проверялись на отдельном эмуляторе; на телефоне установлен актуальный выпуск без удаления пользовательских данных. Повторный автоматический запуск тестовых ссылок на телефоне ранее отклонён автоматической проверкой разрешений даже после разрешения пользователя; это ограничение не обходилось.

## HTTPS и развёртывание

- `/`, `/privacy/`, `/.well-known/assetlinks.json`, APK: HTTP 200 через HTTPS с проверкой сертификата.
- Asset Links: правильный MIME application/json, публичный SHA-256 сертификата совпадает с APK и keystore.
- SHA-256 APK: `206999d82e6b8bb1efea02118e3dda382f2120d19ce1329a5ed8adba1383e2e9`. Скачанный с сайта файл побайтно совпадает со сборкой.
- Сайт в мобильном браузере 390 px: предпросмотр двух операций виден, горизонтального переполнения нет, ошибок/предупреждений JS нет.
- Payload обрабатывается из fragment локально. Проверка HTTP-запроса подтверждает `GET /` без fragment; на сайте отсутствуют fetch/аналитика/API хранения питания.
- Выпуск сайта: `/opt/foodbridge/releases/20260910T230821Z`.
- Caddy обслуживает FoodBridge отдельным конфигом; `caddy validate` и reload успешны, служба active.
- SHA-256 исходного Caddyfile и конфига investing совпали с исходными; защищённый соседний сайт продолжает возвращать ожидаемый 401.

## Обнаруженные и исправленные проблемы

- Строгое распознавание дублирующихся JSON-ключей, ограничение глубины и размеров, проверка чисел/дат/Unicode, уникальность ID в пакете.
- Подтверждение удаления привязано к текущему запросу, новый intent не получает прежнее согласие.
- Нативное чтение по client ID ограничено собственными записями; проверяются origin и ID, READ_NUTRITION отсутствует.
- Общая блокировка сохраняется до окончания удаления и обновления истории даже при отмене Activity/корутины.
- Отзыв разрешения корректно возвращает кнопку разрешения; все передаваемые нутриенты видны в пакетном предпросмотре.
- Предпросмотр новой ссылки сбрасывает прокрутку; ответ на старый запрос не заменяет новый экран.
- Секреты подписи исключены из Git; фактические пароли и приватный ключ проверены по содержимому публикуемых файлов.

## Практические ограничения

- История последних 1000 ID хранит максимальные ревизии, включая удалённые записи. После очистки данных приложения, переустановки или вытеснения tombstone очень старая ссылка может создать удалённое блюдо заново. Существующие записи дополнительно защищены ревизией Health Connect.
- Пакет последовательный, без общей транзакции. Выполненные действия не откатываются при ошибке соседнего действия.
- Исправлять/удалять можно записи FoodBridge по их ID. Другие приложения управляют своими записями самостоятельно.
- Полностью фоновое выполнение без открытия Activity не реализовано. Быстрый сценарий — открытие ссылки, краткий экран результата, возврат назад.
- Ключ для будущих обновлений находится в `private/foodbridge-release.p12`, пароли — в игнорируемом `signing.properties` внутри проекта. Сохраните оба файла отдельно; их нет в публичном репозитории и архиве исходников.
